# office-hub

社内業務システムを1つの入口に束ねたプラットフォーム。利用者はポータル画面にログインし、そこから自分が使えるシステムへ移動する。

第1弾として **備品在庫管理システム** を実装している。「在庫の**今**」だけでなく「**そうなった経緯**」を追跡できることを設計の中心に据えた。

## 設計上の要点

### 基盤

1. **ロールはシステムごとに持つ** — `users.role` ではなく `system_user_roles` に (ユーザー, システム, ロール) を保持する。同じ人が「在庫では管理者、他システムでは一般」という状態を表現できる
2. **利用権限とポータル表示を単一の情報源にする** — `system_user_roles` に行が無いシステムはポータルに表示されず、API も 403 を返す
3. **システム利用の認可はミドルウェアで一括** — 個別実装の権限チェック漏れが他システムのデータ露出に直結しないようにする

### 備品在庫管理

1. **在庫数をカラムで持たない** — 在庫の唯一の正は在庫トランザクションの累計。`item_stocks` は同一 DB トランザクションで更新する集計キャッシュとして扱い、整合性検証コマンドで乖離を検出する
2. **在庫更新は悲観ロック、マスタ編集は楽観ロック** — read-modify-write となる在庫引き落としは行ロックで直列化し、競合頻度の低いマスタ編集はバージョン番号で衝突検出する
3. **在庫履歴は更新も削除もしない** — 誤登録の訂正は逆仕訳（取消トランザクション）で相殺し、監査証跡を維持する
4. **在庫変動 API は冪等** — `Idempotency-Key` により、通信リトライやダブルクリックでの二重計上を防ぐ
